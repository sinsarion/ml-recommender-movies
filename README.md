## Библиотеки и алгоритмы для построения рекомендаций
Для реализации ядра Machine Learning (ML) при построении рекомендаций были выбраны библиотеки LightFM и PyTorch.
- **[LightFM](https://github.com/lyst/lightfm)** - это реализация на Python ряда популярных алгоритмов рекомендаций для явной и неявной обратной связи, включая эффективную реализацию потерь рейтинга BPR и WARP, т.е. **гибридная модель**, которая сочетает:

  - Это классическая нейросетевая модель, применимая к задачам рекомендаций, когда у нас есть матрица взаимодействий между пользователями и объектами (в нашем случае — пользователи и фильмы).

## Типы рекомендательных систем

Существуют три основных типа рекомендательных систем:

1. Content-Based: ***на основе содержимого***
- Рекомендуются фильмы, похожие на те, что пользователь уже смотрел. Для этого требуются признаки фильмов: жанры, актёры, описание, год, рейтинг и т.д.

2. Collaborative Filtering: ***на основе поведения пользователей***
- Рекомендуются фильмы, которые смотрели другие пользователи с похожими интересами. Требуются взаимодействия: кто что смотрел, лайкнул, добавил в избранное и т.д.

3. Hybrid: ***гибридные***
- Комбинация двух подходов: Content-Based (контент) + Collaborative Filtering (поведение пользователей)

Гибридный подход часто даёт лучшие результаты. Поэтому для реализации рекомендательной системы была выбрана именно он.

## Краткое описание библиотеки LightFM

LightFM — это библиотека, специально созданная для построения рекомендаций. Она использует **гибридный подход**, т.е. объединяет **collaborative filtering** и **content-based** рекомендации.

Основные возможности LightFM:
- Поддерживает implicit/explicit данные
- Учитывает характеристики пользователей и фильмов (жанры, актёры и т.п.).
- Работает как обычная ML-модель: обучение, сохранение весов, предсказания, т.е. можно обучить и сохранить модель, затем использовать в сервисе

Обладает следующими преимуществами:
- Поддержка **гибридных моделей**: использует взаимодействия + признаки объектов
- Поддержка различных **функций потерь** с парными потерями (pairwise loss) (например, WARP или BPR)
- Оптимизированная работа с разреженными матрицами
- Простота интеграции и хорошая интерпретируемость

Библиотека LightFM строит рекомендации на основе:
- User-Item Interaction Matrix (в виде разреженной матрицы)
- User Features (параметры пользователя)
- Item Features (атрибуты фильма — жанры, теги, актёры и пр.)

---

## Принцип работы LightFM для построения рекомендаций

- Каждому пользователю и фильму присваивается **вектор признаков** (embedding)
- Взаимодействия (лайки) используются для обновления этих векторов
- **Item features** помогают обобщать на новые/редкие фильмы
- Делаются предсказания с помощью функции: `dot(user_vector, item_vector)`

### Шаг 6. Создание и обучение модели LightFM на основе сгенерированных `user-item matrix` и `item features` матриц

Для этого был создан скрипт `train_lightfm_model.py` который выполняет следующие действия:
- Загружает матрицы `interactions.npz` и `item_features_all.npz` из файлов
- Инициализирует модель LightFM, используя для оптимизации обучения функцию потерь `WARP`:
  ```python
  model = LightFM(loss='warp', no_components=64)
  ```
- Обучает модель 30 эпох
  ```python
  model.fit(interactions, item_features=item_features, epochs=30, num_threads=4)
  ```
- Сохраняет обученную модель в файл `lightfm_model.pkl`

**Функция потерь** - важнейший компонент, используемый во время обучения модели. Эта функция измеряет разницу, или "потерю", между предсказаниями модели и реальными значениями, полученными из обучающих данных.
Высокое значение потерь означает, что предсказания далеки от истины, в то время как низкое значение потерь указывает на то, что предсказания близки к реальным значениям. Основная цель обучения модели - минимизировать функцию потерь, тем самым сделав модель как можно более точной.

LightFM в основном использует функцию потерь **WARP** для факторизации матриц. Мы выбрали именно эту функцию.

Примерный алгоритм работы **WARP loss**: случайным образом выбираются выходные метки модели, пока не будет найдена пара, которая, как знает алгоритм, неправильно помечена, а затем будет применено обновление только к этим двум неправильно помеченным примерам.

Почитать про применение **WARP** для обучения можно например [здесь](https://ethen8181.github.io/machine-learning/recsys/5_warp.html).

В нашем случае функция потерь **WARP** максимизирует вероятность того, что положительный элемент будет выше по рейтингу, чем отрицательный.

Создание и обучение модели скриптом `train_lightfm_model.py` происходило достаточно долго (на ноутбуке MacBook Pro), несколько часов (точное время не замерялось). 

В результате работы скрипта был сгенерирован и обучен файл модели **lightfm_model.pkl**, размером **301,5 МБ**.

### Шаг 7. Оценка качества обученной модели LightFM с помощью метрик: `precision@k`, `recall@k`, `AUC`

Для реализации оценки качества сгенерированной и обученной модели LightFM `lightfm_model.pkl` был написан скрипт `evaluate_lightfm_model`.

**NB!** Скрипт на ноутбуке MacBook Pro работал почти 5 часов.

В модуле `lightfm.evaluation` уже содержится готовый функционал для оценки моделей.

Скрипт `evaluate_lightfm_model` последовательно вызвал функции оценки `precision_at_k`, `recall_at_k`, `auc_score` из модуля `lightfm.evaluation` по выбранным метрикам:
  ```python
  def evaluate_model(model, interactions, item_features):
    print("Оцениваем качество модели...")
    results = {}

    if "precision@10" in METRICS:
        results["precision@10"] = precision_at_k(
            model, interactions, item_features=item_features, k=10
        ).mean()

    if "recall@10" in METRICS:
        results["recall@10"] = recall_at_k(
            model, interactions, item_features=item_features, k=10
        ).mean()

    if "auc" in METRICS:
        results["auc"] = auc_score(
            model, interactions, item_features=item_features
        ).mean()

    return results
  ```

Буква **k** в метриках - означает количество топ-рекомендаций, которые мы отдаём пользователю, при k = 10 это ТОП-10 фильмов.
Выбрано **k = 10** потому, что считается что 10 фильмов - это золотая середина: достаточно, чтобы пользователь нашёл что-то интересное в ТОП-10, но не слишком много.

- **precision@10** означает: "точность среди 10 лучших фильмов, рекомендованных пользователю"
- **recall@10** означает: "доля релевантных фильмов, попавших в эти 10 рекомендаций"

Результаты работы скрипта (k = 10):
- Метрика `precision@10` = **0.5232**
- Метрика `recall@10` = **0.1178**
- Метрика `AUC` = **0.9962**

### Оценка результатов

1. `precision@10` = **0.5232**

Значение 0.5232 означает: в среднем 5.2 фильма из 10, которые рекомендует модель — действительно интересны пользователю.
Чем выше `precision@k`, тем точнее выдача.

2. `recall@10` = **0.1178**

Значение 0.1178 означает: из всех возможных "интересных" фильмов пользователь видит примерно 11.7% в рекомендованном топ-10.
Эта метрика показывает насколько хорошо мы охватываем интересы пользователя.
Обычно **recall** ниже **precision**, особенно при малом **k = 10**.

3. `AUC` = **0.9962**

`AUC` (Area Under the Curve) — измеряет, насколько хорошо модель ранжирует положительные взаимодействия выше отрицательных.
Значение **0.9962** - означает почти идеальное качество. Модель отлично себя ведёт в сортировке фильмов для пользователя.

**Вывод**: модель обучилась довольно качественно — это особенно заметно по метрикам `AUC` и `precision`.

LightFM хорошо справляется с ранжированием и находит достаточно интересные фильмы для пользователей.

# Подход к построению модели NeuMF на PyTorch

Модель NeuMF (Neural Matrix Factorization) — это современный подход к рекомендательным системам, который объединяет два подхода:
- **GMF (Generalized Matrix Factorization)** — классическая матричная факторизация, работающая с взаимодействиями.
- **MLP (Multi-Layer Perceptron)** — многослойный персептрон, позволяющий находить сложные зависимости между пользователями и объектами.

Мы реализовали архитектуру NeuMF вручную с использованием библиотеки PyTorch:
- Каждый пользователь и фильм получают **векторное представление (embedding)**.
- Поток GMF обрабатывает взаимодействие как поэлементное произведение этих векторов.
- Поток MLP объединяет те же векторы в один и передаёт через несколько полносвязных слоёв.
- Финальный слой объединяет выходы GMF и MLP и подаёт их на линейный выход с **Sigmoid** для предсказания вероятности лайка (0 или 1).
- В архитектуре используется **Dropout** и **BatchNorm** для повышения устойчивости и обобщающей способности.

Положительные примеры были получены из MongoDB (лайки), отрицательные — сэмплированы случайным образом (отсутствие взаимодействия). Итоговый датасет содержит:
- `user_id`, `movie_id`, `label` (0/1)

Обучение производилось с помощью **BCELoss** (бинарная кросс-энтропия) и оптимизатора **Adam**. Объём датасета — более **30 млн** пар.

Модель успешно обучилась за 30 эпохах, и была сохранена в файл `neumf_model_v2.pth`.

# Документация API рекомендательной системы на базе LightFM

## Краткое описание 

API предоставляет персонализированные и не персонализированные рекомендации фильмов на основе модели LightFM, обученной на датасете `MovieLens 32M`. Сервис возвращает подробную информацию о фильмах, включая рейтинги, жанры и ссылки на внешние источники (IMDb и TMDB).

---

## Получение персонализированных рекомендаций

### `GET /recommendations/{user_id}`

Получение списка рекомендованных фильмов для конкретного пользователя на основе обученной модели LightFM.

**Параметры запроса:**
- `user_id`: идентификатор пользователя (строка или число)
- `dataset`: имя датасета (в данный момент поддерживается только `movielens_32m`)
- `k`: количество фильмов в рекомендации (по умолчанию `10`)
- `ml_model`: **lightfm** или **neumf** (выбор обученной модели для построения списка рекомендаций) 

**Пример запроса:**
```
GET /recommendations/123?dataset=movielens_32m&k=10&ml_model=neumf
```

**Пример ответа:**
```json
{
  "user_id": "8881",
  "has_personalization": true,
  "recommendations": [
    {
      "id": 188,
      "title": "Prophecy, The (1995)",
      "avg_rating": 3.3315135542168677,
      "genres": [
        "Fantasy",
        "Horror",
        "Mystery"
      ],
      "imdb_id": "114194",
      "tmdb_id": "11980",
      "imdb_url": "https://www.imdb.com/title/tt0114194",
      "tmdb_url": "https://www.themoviedb.org/movie/11980"
    },
    ...
  ]
}
```

Если пользователь не найден — API автоматически вернёт результат для не персонализированного пользователя на основе средней оценки фильмов.

## Получение не персонализированных рекомендаций

### `GET /recommendations`

Выдаёт список самых популярных фильмов по среднему рейтингу.

**Параметры запроса:**
- `dataset`: имя датасета (например, `movielens_32m`)
- `k`: количество фильмов в рекомендации (по умолчанию `10`)
- `ml_model`: **lightfm** или **neumf** (выбор обученной модели для построения списка рекомендаций) 

**Пример запроса:**
```
GET /recommendations?dataset=movielens_32m&k=10&ml_model=neumf
```

**Пример ответа:**
```json
{
  "user_id": "",
```

## Прочее
- Все ответы кешируются в Redis.
- Ограничение: 2 запроса в секунду на пользователя (rate-limiter)
- Данные поступают из БД PostgreSQL, схема `movielens_32m`
- Предсказания делаются через LightFM + item features (жанры, теги, рецензии)
